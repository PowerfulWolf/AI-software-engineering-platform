# Controlled service restart

## Scope and failure mode

Applies to one local Console Host, its HTTP writers, Manager Operations, index worker and owned native/tool
processes. Task/Run state, model outcome, lease finish and process liveness are distinct facts. Silent
`thread.join(timeout)` plus daemon abandonment is not stop proof. Uvicorn signals must coordinate before
`should_exit`, not raise from lifespan after shutdown has already begun.

This contract drains an already claimed complete Operation, including subsequent authorized roles with
fresh claims. It does not force-cancel synchronous providers, create shutdown verdicts, refund budgets,
change continuation cause/kind or fabricate original `ExecutionCaptureStop` records.

## Signatures and ordering

```python
# web_console/shutdown.py
gate = ServiceWriteGate()
lease = gate.acquire_write()  # rejects ServiceDraining atomically after drain begins
worker_lease = lease.retain()  # admitted actual threadpool work survives caller cancellation
worker_lease.release()
gate.begin_shutdown()
gate.await_shutdown(timeout)  # ShutdownResult(state, safe_summary, active_writes)
gate.cancel_shutdown()

# web_console/core.py
console.begin_shutdown()
console.await_shutdown(timeout)  # durable terminal Operation + dispatcher exit required
console.cancel_shutdown()        # timeout only, persistence-failure latch refuses
console.close(timeout=5)         # explicit READY/REFUSED result

# owned_processes.py
registry = HostOwnedProcessRegistry()
with registry.operation_scope(operation_id):
    execute_and_persist_complete_operation()
registry.await_stopped(timeout_seconds)  # every registered group/pipes must be verified

# service_lifecycle.py
coordinator = ConsoleShutdownCoordinator(console=console, write_gate=gate,
    knowledge_worker=index_worker, owned_processes=registry)
coordinator.begin_shutdown()
result = coordinator.await_shutdown(timeout)
```

Fixed order: close write admission + Console submit/claim admission + future index ticks → wait admitted
HTTP writers → wait claimed Operation terminal persistence + real dispatcher exit → wait real current
index tick → verify registry → publish exact instance and request-bound READY atomically/fsync → set
Uvicorn exit → script verifies actual exit → replace service under the same lock.

Operation active count stays positive through final `OperationStore.succeed/fail` and trusted process
scope exit. Submit and claim share the same short lock as drain. Queued unclaimed Operations stay QUEUED.
Stored terminal persistence or claim failures latch REFUSED; stopped/dead dispatcher alone cannot clear it.
HTTP lease admission covers all mutating methods, including settings/upload; actual sync worker retains
an admission lease even if the ASGI caller disconnects. GET continues reading and cannot start delivery.

## Private wire contract

`ServiceLifecycleStore(root)` accepts only its fixed basenames:

| File | Typed model / fields |
|---|---|
| `console-service-instance.json` | ServiceInstance: schema_version=v1, instance_id=`console_instance_`+hex32, pid>1, state, started_at, updated_at, safe_summary |
| `console-service-shutdown.request.json` | ServiceShutdownRequest: v1, request_id=`console_shutdown_`+hex32, instance_id, pid, action=SHUTDOWN/RESUME, state=REQUESTED, requested_at, timeout_seconds=.01..3600 |
| `console-service-shutdown.result.json` | ServiceShutdownResult: v1, request_id, instance_id, pid, state, recorded_at, safe_summary |

State values: STARTING, RUNNING, DRAINING, READY, REFUSED. STARTING is published before workers, RUNNING only after successful listener startup. All timestamps aware UTC; summaries fixed Chinese text,
extra fields rejected. These files describe service lifecycle, never original Run stops/verdicts. Static
`schemas/console-service-*.schema.json` are generated by `scripts/generate-controlled-restart-schemas.py`.
Reads are 8192-byte bounded, O_NOFOLLOW, owner-checked regular files, nlink=1, mode0600. Writes use same-dir
temp+0600+fsync+atomic replace+directory fsync. Directory must be owner-controlled and not group/world writable.
Failure publishing proof retains the old server; an unverifiable marker is never permission to replace.

## Script and server contract

```text
scripts/ase-console-service.sh start|stop|restart|resume|status|logs
scripts/ase-console-lifecycle.py locked <action>  # fixed script exec under OS-released flock
ASE_SERVICE_STATE_DIR = absolute private directory, otherwise XDG_STATE_HOME / home fallback
ASE_SHUTDOWN_TIMEOUT_SECONDS = .01..3600, default300
console-service-replacement.lock = regular0600 owner/nlink1 flock file
```

Start additionally requires a fresh RUNNING instance with this child PID and a different nonce from
the predecessor, not only an executable alive check. CLI start/stop/restart/resume and supervisor
configuration-apply replacement share one nonblocking
flock across entire replacement. A competing action is refused, not interleaved. The fixed `locked`
script entry validates its inherited descriptor/inode. New detached children must not inherit it.
Secrets remain loaded only in the launch-child subshell; lifecycle helpers never load `runtime.env`.
Supervisor stays available after REFUSED and is stopped only after verified child exit for direct stop.

`ControlledConsoleServer` owns SIGTERM/SIGINT before ordinary Uvicorn exit. Repeated signals during
drain cannot set force_exit. New exact requests can retry REFUSED; RESUME only succeeds while still
alive after a timeout, never after READY/persistence-failure latch. `READY` requires matching request,
instance and PID; script then waits real PID exit, never sends KILL. Start/dead records require exact
READY/request/result or refuse. An initial empty lifecycle directory is allowed for first startup.

## Validation and error matrix

| Input or failure | Required result / preserved facts |
|---|---|
| Real active Operation, writer, provider/tool or index | DRAINING; no READY or replacement |
| All durable work, threads and owned process groups/pipes complete | exact READY then exit, one successor |
| Deadline while active | REFUSED; old PID/threads retained, reads available; retry or timeout-only resume |
| Operation terminal/claim store failure or proof write failure | sticky REFUSED; no resume/READY |
| New mutation/submit/claim after drain | Chinese SERVICE_DRAINING / no durable submission; queued untouched |
| Request canceled but sync worker still writing | retained lease; no premature READY |
| Old nonce/PID/request or stale READY | refuse without process signal/replacement |
| Symlink/foreign uid/link/oversize/malformed record | fixed Chinese refusal, no secrets or traceback |
| CLI/apply replacement conflict | shared lock; one owner, no second child |
| Missing old handshake or unproven dead PID | preserve record; maintenance upgrade/recovery required |
| Repeated TERM/INT | single drain, never Uvicorn force-exit |

Good: native execution records its actual result/stop, Task/queue finish normally, Operation seals,
READY publishes, then service restarts. Base: idle service drains promptly. Bad: using service PID
disappearance, daemon death, lease expiry, manufactured provider error or old READY as stop proof.

## Required tests and assertion points

- `test_core.py`/`test_shutdown.py`: original red close/submit reproduction; final persistence barriers,
  queued preservation, writer cancellation/retention, claim/terminal/BaseException latch, safe resume.
- `test_index_worker_shutdown.py`: actual active tick cannot silently survive successful close.
- `test_service_lifecycle.py`: typed/fixed/secure store, complete conjunctive readiness, stale facts.
- `test_controlled_host.py`: real Uvicorn subprocess/HTTP, repeated signals, refused timeout,
  final record before actual exit; no production configuration/database.
- `test_console_service_script.py`: exact instance handshake, refusal keeps PID+supervisor, resume,
  legacy/dead/stale identities, shared lock, apply idempotence and removed-secret environment isolation.
- `test_owned_processes.py` and adapter/executor tests: real process groups, bounded pipes/stop,
  uncertain cleanup blocker, structured/native/tool/verification subprocess coverage.
- Native directory chooser uses the same owned process seam within HTTP write scopes. Port binding
  and lifecycle identity publication precede starting any Operation/index worker; failure starts neither.
- Known index/process uncertainty and terminal-record failures reject RESUME before publishing RUNNING;
  pure waiting timeouts can resume only after that proof is safely persisted under Console admission lock.
- `test_controlled_restart_schema.py`: generated typed JSON Schema parity.

## Existing-data treatment and rollback

No SQL migration or historical Task/Run/Operation/approval rewriting. Existing K1 unknown Run and retained
files stay unchanged; this prevents future ordinary restart losses, does not fabricate its missing stop.
Old running binaries cannot acquire the new handshake via disk changes; follow
[`docs/operations/controlled-service-restart.md`](../../../docs/operations/controlled-service-restart.md)
for one-time maintenance upgrade. Crash/OS kill/outside-Host CLI still require original recovery.
Rollback: successful controlled stop first, revert code/sync dependency and start. Never use rollback
as a way to interrupt active work or bypass missing stop proof.
