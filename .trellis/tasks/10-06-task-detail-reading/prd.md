# 需求与任务详情信息层级及稳定阅读

## 目标与边界

任务详情按当前状态/原因/责任/下一步、最新独立验收反馈、完整历史、报告、模型与工程信息组织。
解决心跳更新时历史 DOM 更换导致选区和阅读位置丢失，以及多层限高滚动造成内容难以阅读。
仅修改前端 app.js/style.css、相关增量 tests 和 specs；不修改 API/Schema、Task、Operation、审批或队列。

用户补充需求：需求详情不再使用最多 13 个平铺模块，以独立卡片明确组织为四章：
当前进展、产物与交付、完整交付记录、工程参考。阶段文档必须保持同级样式；
历史折叠项属于记录章，不能视觉上延续为阶段产物。章内副标题与工程元数据层级明确。

## 验收

- 顶部直接可见当前任务状态和原 typed execution 的中文处理建议；历史反馈明确标为当次记录。
- 完整历史保留全部行/原顺序/身份/来源，未提供事实不猜测修复或通过；报告正文安全 textContent 渲染。
- 历史行、报告、已完成模型调用按精确事实保留 DOM，heartbeat 或新增历史不丢选区/展开/滚动。
- Task 详情提供阅读暂停/恢复：只冻结无写操作的 Task 阅读区，后台 snapshot 继续获取。
  新进展明确提示；Project/Task 消失或导航必须解除冻结；Requirement 精确审批控件不被暂停。
- Task 使用一个主要垂直滚动容器；长文/命令/路径完整换行，390/1024/1440px 无横向溢出。
- Task 参照需求详情明确四章：当前进展、产物与报告、完整执行记录、工程参考。
  模型调用属于历史，工程信息属于参考；同级折叠字号/边框/间距一致，内部元数据才降级。
  只固定关闭/阅读工具栏，长标题可随正文滚动，避免占满视窗。
- Requirement 主标题只有上述四章；章节导航只滚动，不提交或切换事实。
  当前阻塞、知识确认、产品回复和精确审批仍在当前进展，工程参考不能承载当前审批。
  新增章节父容器必须 keyed，跨轮询保留文档选区、讨论草稿和历史展开。
- 需求与任务名称和状态在同一行，状态位于标题右侧；长标题自然换行，窄屏状态不被挤出边界。
- 需求抬头四个元素作为一个整体：上行“需求详情”与管理控件统一紧凑字号，下行标题与状态相邻。
  关闭控件的视觉降级不能覆盖编辑、重启、删除等控件的权限或 primary/danger 颜色。
- 真实 Chrome fixture 与受影响 JS 增量回归通过，不运行全量测试，不调用生产写 API。

## 回滚与存量

无数据迁移。前端资产更新后刷新页面；回滚 app.js/style.css 并刷新即可，原历史/批准/候选和模型事实保留。
