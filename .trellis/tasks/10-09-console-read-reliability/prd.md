# 控制台稳定、及时展示现有需求

## 目标
修复真实 K1 控制台读取失败，并缩短刷新延迟，保留完整交付与处理历史。用户继续自行审批与交付。

## 范围
- 核对处理报告 immutable key 算法演进造成的旧记录读取失败，保持全部原始 bytes/hash、关联与权限验证。
- 单次只读 snapshot 复用已完整校验的同一历史 prefix，减少退休需求/统计重复读；不跨请求缓存，不截断历史。
- 前端需求展示不等待慢的独立操作历史请求；操作历史读取失败保留旧内容但禁用需要当前 facts 的命令。
- 安全中文错误与请求生命周期，不泄漏配置或密钥。

## 验收
- [x] 真实现存记录只读投影成功，原文件/SQL不变。
- [x] 合法旧 key 可展示；改键、改 hash、跨 Task/范围、错误联结仍拒绝。
- [x] 每份 Requirement history 在一次 snapshot 至多完整读取一次，退休校验仍完整。
- [x] Team 成功立即展示，不等慢 Operations；失败保留旧历史并禁不可信控制。
- [x] 增量回归、Ruff、Mypy、必要浏览器检查通过，不运行全量tests。

## 回滚
撤回本任务代码与前端，保留所有存量业务事实；运行中的服务由用户受控重启加载。
