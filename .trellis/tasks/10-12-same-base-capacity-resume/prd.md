# Problem

A normal target project can hit a claimed final-input `CONTEXT_CAPACITY` wait while
Coder has lawful dirty progress. Fixing the ASE runtime input assembly does not change
that project's approved code commit. The public baseline proposal currently accepts
the same target base, but execution rejects its final `ExecutionBaselineBinding` because
`source_rebind` requires a different execution base. Users must not invent an unrelated
business commit merely to continue an uninvoked role after a platform fix.

# Scope

Enable one exact same-base capacity refresh through the existing public
PROPOSE_EXECUTION_BASELINE → exact engineering PAUSE → separate RESUME contract.
Do not change Task intent, original base, worktree, branch, complete dirty capture,
permissions, product approval, work budget, original no-start facts or role separation.
Implementation is explicitly authorized with the independent context_capacity_resume purpose and target omitted/None; the platform derives the unchanged execution base from trusted facts.

# Acceptance

1. A real public Host fixture executes Coder attempts 1 and 2 with owned native process
   timeout/stop receipts and retained dirty changes, then genuinely claims attempt 3 and
   records a final-input capacity stop before the provider invocation starts.
2. Same-base preserve-draft proposal and exact PAUSE execution succeed; original Task,
   events, WorkItem, attempt 3, branch, HEAD, index and complete inventory remain intact.
3. A new optional binding digest pins the exact capacity receipt. Missing/default digest
   preserves historical serialized payloads and SHA-256 values. A caller-supplied digest
   alone grants no authority.
4. Separate exact RESUME releases only this held generation. A fresh claim/Context/Run
   uses baseline inventory admission after old native receipts are explicitly retired.
5. Coder completes the retained work; different QA and Reviewer independently validate
   the same candidate and the original Task reaches DONE without a new Requirement/Task.
6. Same-base without exact capacity evidence, wrong receipt/claim/source/Context, a real
   model start, changed inventory, source-changing reapply, native-rule change, automated
   authority, direct RESUME and stale approval all fail before unsafe queue/Git mutation.
7. Existing different-source and stopped-provider/completed-output flows retain their
   contracts. Schema regeneration and old wire/hash fixtures remain compatible.

# Existing data

No SQL migration, Task reset, altered attempt or overwritten journal is allowed. Current
nonterminal exact capacity waits may prepare a fresh plan under the compatible runtime,
review full retained progress, approve PAUSE, then separately continue. Old plans are not
silently repaired. Historical source changes and terminal recovery keep existing rules.

# Validation and rollback

Run the new public integration regression in its isolated ASE_TEST_MYSQL_DSN window,
then targeted binding/Schema/store/queue/Console negative and compatibility tests after
implementation. Full-suite execution belongs to the user. Revert unconsumed code safely;
once additive bindings exist, retain compatible readers and prefer a forward fix.
