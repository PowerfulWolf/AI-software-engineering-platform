## Scope and result

**PASS for the bounded independent regression scope: 34 tests.**

- For Coder, QA and Reviewer separately, an actual knowledge consultation raises a blocking
  Gap before that role's delivery Agent runs. SQLite retains IMPLEMENTING, QA or REVIEW,
  respectively, with no terminal failure. After exact resolution approval, fresh store,
  client and context-builder instances resume the same Task to DONE. The old event prefix,
  original Gap and Resolution remain; the new run/context references the previous binding
  and preserves the frozen knowledge snapshot. The three delivery artifacts have distinct
  fixture Agent identities.
- QA, Reviewer and Manager gates reject missing proof, nonexistent proof, forged digest,
  and a correctly digested proof for an earlier stage. Delivery transitions reject absent
  artifact chains.
- Enabled/disabled observations come from actual consultation calls, typed search/read
  evidence and immutable model-call records. Enabled knowledge supplies the exact cited
  answer; disabled knowledge produces a Gap. The deterministic fixture records 10 extra
  tokens and 5 extra milliseconds for the enabled consultation, recomputed from call facts.
- Real conflicting reads produce a Gap. Cross-Project search and citation-read attempts are
  rejected and cannot supply an answer. A real document retirement removes the answer from
  a new snapshot, while the historical frozen snapshot remains readable.
- Spec and background sources retain distinct citation scopes. The evaluation accepts the
  correct Spec decision and fails an intentionally incorrect background decision, both
  generated from actual retrieved evidence.
- An approved `PROPOSE_LEARNING` resolution creates a proposal without publishing. A second
  exact human Learning approval publishes and selects the Project Knowledge document. A
  fresh Requirement snapshot can retrieve/cite the approved answer and avoids the same Gap;
  the original frozen snapshot and original Gap are unchanged.
- Evaluation reports round-trip through `KnowledgeRecordStore` and recompute identically
  from their persisted observations.
- Approved Task resolutions become standard Evaluation `HumanActionEvent` facts with
  `CLARIFY_REQUIREMENTS` and the exact resolution evidence URI. Reopening both stores and
  repeated discovery through duplicate input stores does not duplicate events. An upstream
  Requirement resolution records one distinct event for each associated child Task. Other
  Task/Requirement resolutions, or upstream resolutions without a current Requirement
  binding, do not enter the case.
- Reconstructing the evaluation trace from SQLite state events, sealed artifacts and durable
  evaluation events changes an otherwise ELIGIBLE completed delivery to INELIGIBLE with
  `HUMAN_INTERVENTION`: autonomous numerator becomes zero while completed cases remains one.
  RuntimeSession integration verifies the clarification event exists after CaseStarted and
  before the first Agent request, and the fixture still completes all four roles to DONE.
- An approved QA Gap first resumes the exact interrupted candidate A. A later candidate B
  receives a new consultation and resume record whose `previous_resume_sha256` points to the
  first exact resume. Changing candidate before that first exact recovery is rejected.
- A proof generated by a real successful delivery cannot authorize the same Task under a
  different candidate revision, consultation source revision, parent context, final context
  or run, even when the replacement knowledge manifest has a valid recomputed digest.
- A pre-upgrade crash after the implementation artifact is sealed but before the QA state
  event is persisted resumes the same SQLite Task using one-time legacy admission. Only QA
  and Reviewer run; the original implementation, plan, Context bytes and event prefix remain.
  Admission rejects artifacts added later, a changed digest under the same artifact ID, and
  receiptless work on a Task already admitted while NEW. Replaying admission does not extend
  its frozen legacy artifact set.
