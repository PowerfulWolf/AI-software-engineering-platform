# 完成面向产品用户的交付恢复重构

## 目标与授权

补齐 2026-10-04 方向复盘与产品交付方案的完整目标。此前仅完成首轮 Coder 中断、状态/历史与安全删除，不能把该切片称为整体重构完成。用户追问未完成部分会继续影响需求交付；沿用此前重构、提交推送与空闲部署授权继续实现，不再次要求产品确认工程细节。

用户暂停业务交付的指示保持有效：不得新建生产需求、恢复已删除 K1 或调用生产业务模型。只运行相关增量测试；全量测试仍由用户负责。

## 完整要求

1. 工程中断在冻结授权和预算内沿用同 Task、分支与工作区处理；多轮 Coder、合法 progress 与 QA/Review 返工不能只有第一轮获得正确中断处置。每次模型调用有新 Run/Context/真实 claim，记录不覆盖；不在同 Run 上 dirty fallback。
2. 所有已支持失败原因共用 typed 处置与责任契约：自动重试/返工、团队等待、工程处理、产品决定、真正终止。可等待问题保存 Task 交付 checkpoint，在 WorkItem 表达等待并释放租约。模型/Manager/UI 不各自推断或审批。
3. 真实执行不确定、权限/证据拒绝必须保存现场，有明确责任、前提及可操作恢复途径；不能只有“无需产品操作”标签而无处置事实。自动动作与真实人工决定分别审计。
4. Product 内容与工程授权分开。可信本机 operator 明确产品/工程身份和权限，精确 ProductSpec 仍由产品批准；Manager 仅调用已授权受控能力，不能自批、改 verdict 或获得 ambient shell/store。
5. 普通平台版本更新与目标源码更新分开处理。版本化工程 policy 在条件成立时允许确定性、精确事实绑定的工程恢复；超出 policy 的新范围、能力、凭据、预算、冲突交相应授权者，不以重建需求代替恢复。
6. Planner 将完整已批准范围安排为有界串行步骤和 checkpoint，Coder 有可执行窗口与完成预留。必需验证入口/能力在实施前检查，避免开发后才发现无法验收；不增加 DAG 或单 Task 多角色并行。
7. 产品页面展示上述同一处置事实的阶段、执行状态、责任、原因和下一步；完整保留 QA/Review finding、Coder 输入/候选、自动/人工处置与所有轮次。技术证据折叠展示，未知状态如实显示。
8. 正常公开入口增量组合覆盖正常交付、多轮 QA/Review 返工、各角色中断/重启、知识解答、环境修复、基线变化与旧授权、漂移/越权/预算耗尽。至少正向/拒绝/重启幂等断言；保留独立 QA/Review 和同候选 SHA 验收。

## 工程约束与允许路径

允许 src/ai_software_engineer/、对应 tests/、schemas/、Schema 同步 scripts/、docs/ 与 .trellis/spec/ 的相关模块。禁止密钥、sidecar、生产数据库、审计临时文件入库；不直接生产 SQL 修状态、不清理 dirty worktree。平台已存在的 .ase/ 不提交或删除。

自动恢复不能绕过权限/证据或伪造停机。未知调用、无法证明进程停止、损坏输入与新能力必须安全停止并进入明确工程通道；这属于产品契约中的正常边界，不等于要求万能修复或零 Bug。旧终态使用审计兼容流程，不能重新打开。
