# 反复中断的根因与预防

根因属于跨层契约、隐含假设和组合测试缺口：provider 错误、合法脏草稿、权限违规、执行器停机和恢复授权混为一个失败；阶段标签又被用来代替真实执行状态。逐条加历史恢复分支只能绕过局部事实，不能建立可预测的正常交付行为。

本轮将模型故障、工作成果、预算决定和准入分开。新 Task 冻结 policy；可信 runner、完整 Git ignored inventory、receipt 和 admission 共用实际 Worker/Dispatcher。产品视图只消费 typed facts，技术决策准确交工程责任，保持独立 QA/Review 和完整历史。

独立复核扩展到遗漏的成功路径、缺失停机证明、预算耗尽和文件/SQL 崩溃窗口，补了可重复的正反例。Schema-valid output 不是权限通过，capture hash 不是可信停止，lease 失效不是进程不存在，admission 已发布也不证明调用未发生。后续新能力必须继续沿这些明确 seam 验收，不再次堆叠 prompt 特例。

能力边界：第一版只自动续跑普通首次 Coder 的合法文本草稿一次；receipt 到预算/队列提交前的重启可重放。admission 发布之后调用不确定时保留现场并走工程处理及正式 recovery，不自动重绑，不退款，不虚构完成。后续扩大范围须新契约和公共组合回归。

产品删除正式撤销继续/审批入口，不抹去工程审计。两个旧 K1 不再被用作未知特例的生产测试环境；后续业务交付等待用户重新决定。
