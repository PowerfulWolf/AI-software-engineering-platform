# Same-base completed-output recovery

## Goal

Let a user preserve the existing requirement's legal development progress when a
native Coder execution has verifiably completed but its output was not accepted,
without entering a Git SHA or changing the code base merely to obtain recovery.
Explain the original unknown output, exact authorization, preparation and actual
role execution separately. Make the owning requirement reachable from Task detail.

## Scope and contracts

- Add purpose `completed_output_rescue`, exclusively for exact
  `CompletedCoderOutputUnavailableProof`; original failed outcome and unknown
  report content stay immutable. It is neither rejected-output nor legacy rescue.
- Public PROPOSE has no target for this purpose. Under the existing Task lock and
  idle queue fence, collector derives the current trusted execution base.
- Preserve the same Task, semantic branch, worktree, HEAD and complete legal draft;
  no code/native-rule rebind, Coder reapply, permissions, budget refund or verdict.
- Require full current inventory/capture, frozen policy, no live original process,
  real old claim, original publication checks and ordinary remaining work budget.
- Approve exact plan as PAUSE with engineering principal, then separately RESUME
  the exact latest binding; normal new Run/Context/claim and independent QA/Review.
- SOURCE_REBIND continues to require a different target. Legacy unknown stop
  semantics, explicit containment approval and historical digests stay unchanged.
- Front end has a visible target-free prepare entry, exact visible approval, truthful
  active RESUME preparation wording, and an owning requirement navigation button.

## Acceptance

1. Same-base completed-output proof produces a stable full plan and exact paused
   binding without changing repository/worktree bytes or HEAD.
2. Wrong purpose/target/mode, missing/foreign/invalid proof, secret or uncovered
   mutation, live execution, stale approval and exhausted budget fail closed.
3. Replays do not duplicate ordinary work reservation; explicit RESUME still uses
   existing frozen queue contracts. The original failed outcome is unchanged.
4. Public command/static Schema agree, generated gates survive regeneration, old
   source-rebind canonical wire/digests remain compatible.
5. DOM tests distinguish current exact active RESUME from unrelated/historical
   operations; no button demands manual SHA for completed-output rescue.

## Allowed paths / validation / rollback

Only related domain/manager/public-command/Schema/UI/test/spec files in this isolated
checkout. No main repository, ASE operation, deployment, production DB or worktree
mutation. Run incremental Python contract/service tests, affected DOM tests, Ruff
and strict mypy. Root performs public MySQL validation at an idle boundary.

Rollback the code before new records exist. After new purpose records exist,
retain compatible readers and preserved immutable history; do not restore old
work queue rows. Existing completed executions need no direct DB repair: after
loading the compatible service, prepare, approve PAUSE, then explicitly RESUME
the existing requirement via the public API.
