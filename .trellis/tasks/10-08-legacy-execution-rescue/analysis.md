# Bug analysis

## Root cause
A/B/D/E: the old native runner had no prepublished start/stop/capture ledger. Current collector
correctly refused missing facts, but the product path ended with an unactionable maintenance report.
Earlier fixes improved new runs and explanation, without a lawful legacy disposition.

## Why earlier handling was insufficient
Investigation cannot invent old result/stop/before inventory; repeated checks and approving a hash
cannot make those facts exist. An honest new containment + full-current-snapshot contract is needed.

## Additional defect exposed by final history validation
The complete post-delivery `_invocations` traversal initially failed after the native chain reached
DONE. `effective_step` recognized a consumed baseline only on the directly reserved Coder item,
while later QA/Review and rework requests inherit its digest with their own candidate boundaries.
The earlier `_historical_legacy`-only assertion did not exercise that path. The correction verifies
the exact consumption epoch via immutable queue parents and preserves each role's original source;
foreign scopes/allocations, missing/cyclic parents and unrelated/older epochs remain rejected.

Related contract verification also exposed an already committed static union Schema gap:
`role-queue-execution.schema.json` lacked the existing `QueuedWorkItem.wait_disposition` and four
definitions. The runtime models and queue execution store were unchanged by this omission. The
selective schema script now synchronizes the union exactly without changing old model facts;
all six original execution contract checks pass. Check relevant embedded queue schemas alongside
historical readers, rather than testing only the newly introduced plan/binding files.

## Related limitation
The synchronous Responses tool loop currently creates its stopped fact in memory before receipt,
without the native prepublished stop ledger. This is separate from this old local Codex rescue;
the new rescue rejects nonnative/fallback uncertainty. Do not advertise universal provider recovery.
Future ledger work must independently cover synchronous exact request/operations and crash replay.
