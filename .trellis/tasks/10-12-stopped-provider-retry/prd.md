# Stopped provider failure: preserve and retry the same requirement

## Goal and scope

Let an engineering operator preserve legal progress and explicitly retry a real
stopped, failed provider execution after fixing its execution prerequisites. Do
not misclassify a permanent authentication failure as transient, refund it,
rewrite its outcome or require users to invent a Git target.

Initial strict eligibility is Coder FAILED / AUTHENTICATION_ERROR / nontransient
/ no artifact with exact original invocation, capture start, true stop, claim,
current source/scope and full lawful inventory. Generic purpose
`stopped_provider_retry` uses the same base and preserve_draft. Source rebind can
carry the same proof for an explicit different target and retains native-rule
review and approved conflict handling. No policy/invalid/unknown output rescue.

Owner scope: manager proof/baseline, domain Binding/purpose, queue consumer,
published schemas/generator, incremental contracts/services and Trellis specs.
Root owns Console UI and independent public fixture. Others share the checkout;
do not revert their edits. No production/model/main checkout operations.

## Acceptance

- Exact same-base preparation preserves Task, branch, HEAD, worktree and complete
  draft; its proof retains the true failed outcome.
- Exact engineering decision confirms original native/config prerequisites were
  repaired and always PAUSEs; explicit latest-bound RESUME is separate.
- Consume one ordinary work reservation, no refund or duplicated replay; new
  Run/Context/claim and independent QA/Review remain mandatory.
- Original process-stop proof is freshly revalidated before preparation, execute
  and SQL consumption. Missing/foreign/live proof, receipt, accepted artifact,
  policy/invalid output, exhausted work or changed inventory fail closed.
- Schema agrees with models, fresh regeneration keeps standalone embedded gates,
  old absent optional fields preserve canonical wire/digests.

## Verification and rollback

Use incremental proof/service/Git/Schema tests, Ruff and strict mypy; Root owns
public MySQL verification. No full test suite. No database migration: deploy at
an idle boundary, refresh existing requirement, prepare, inspect and explicitly
confirm exact PAUSE, then separately RESUME. Retain compatible readers after new
records exist; never resurrect old work or discard the preserved draft.
