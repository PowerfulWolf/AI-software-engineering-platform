# Goal

让 ASE 作为可进化 AI Team 运作：平台提供可靠编排与受控能力，各 Agent 履行明确职责；Manager
协调项目需要的执行条件与人工介入；开发中得到的项目知识持久化、前端可见、可供后续需求复用。
不将 Swift 等项目技术背景当作平台通用前提，不将安装工具等同于 Agent 自动获得权限。

## Requirements

1. 审计需求创建、Product 审批、Designer、Planner、派发、Coder、QA、Reviewer、交付及知识复用，
   按项目事实、验证要求、执行条件、平台缺陷分类，给出代码/测试证据。
2. 环境、权限、测试数据、工具能力不足由 Manager 汇总成可行动方案；保留候选和证据，不能
   无条件重跑 QA 或误路由 Coder。人工处理结果可审计，只有权限/范围改变才需对应新批准。
3. 开发中确认的稳定项目事实沉淀为有来源、作用域的项目知识；临时环境状态、单次决定与未经
   验证的猜测不自动变为通用规范；不得自动扩权或写项目原生规则。
4. 前端显示沉淀内容、来源、状态、作用域及复用/确认动作；后续需求通过现有知识机制实际消费，
   不只是给文件留记录。当前已批准需求的输入不能被静默改变。
5. 明确 Manager/Product/Designer/Planner/Coder/QA/Reviewer/编排服务职责；能力扩展走提议、
   评估、授权、实现和独立验证，机器策略不是可由 Agent 自行修改的知识。

## Acceptance

- 通用生命周期审计清单逐项给出已验证/缺陷/未覆盖证据；不承诺穷尽所有 bug。
- 环境型 QA 结果在生产入口形成 Manager 处理项，重复继续不消耗 Agent，不丢候选；真正
  代码缺陷仍走独立 finding → Coder。
- 知识从发现/提议到前端显示、确认并被新需求读取有回归测试；重复收集幂等，来源可追溯，
  跨项目、敏感数据、无效来源及自我授权被拒绝。
- 后端类型、Schema、API、前端、测试及规范同步；相关回归、lint/typecheck 通过。

## Boundaries

不引入单任务并行 DAG、自治权限修改、自动安装未知工具或自动 merge。不覆盖历史 Task、计划、
QA/Review。外部环境不满足时报告实际阻塞，不制造 PASS。全量平台现代化按可验证切片推进。
