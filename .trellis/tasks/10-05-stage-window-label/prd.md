# 上游执行窗口展示使用当前可用预算语义

## 问题与目标

Product 首次本地 600 秒执行触顶后，Manager 可以按已批准范围调度 1200 秒重试。
该重试已经执行时，前端仍将 `StageBudget.next_timeout_seconds` 展示为“下次时限”，
让用户误以为页面报告的是另一个尚未启动的 invocation。

该字段由当前容量计数和配置计算可准入的执行窗口，不带当前 invocation 的真实时间事实。
统一展示为“当前可用执行窗口 N 秒”，在执行中和失败后使用同一准确的预算语义。

## 验收标准与范围

- Product、Designer、Planner 的 RUNNING 和 FAILED Operation 均展示“当前可用执行窗口”。
- 不根据 Operation 状态猜测具体模型调用的执行时限、开始时间或剩余时间。
- 容量耗尽继续展示“已达上限”，已有精确审批、重试许可与抑制规则保持原有语义。
- 只改预算文案、对应断言和真实 DOM 增量回归；不增加 Schema 或诊断字段。

## 存量数据处置与回滚

纯读侧展示修复无需改库。历史 bytes/hash、Operation、checkpoint、计数、审批及错误全部保留。
部署前端资产后刷新现有需求页面即可展示正确文案，不需要新建需求或重新批准。
回滚恢复本次前端及文档提交并刷新页面。
