# 有界操作阅读与精确审批

## 目标

当前完整operations列表约25MB，每轮轮询重建全部完整计划。新服务以manifest明确声明
`operation_summary_contract_version=v0.1` 后，前端只轮询有界摘要页并使用ETag；旧服务
保留原完整GET兼容。用户能分页阅读所有操作，每条按需读取完整记录，不固定8条。

## 验收与范围

- 摘要和完整Operation分开保存；不得构造假intent/result让摘要冒充审批。
- 当前Project/Requirement严格隔离，分页外活跃集合也阻止重复提交。
- 摘要或完整详情不可读/漂移时撤销控制资格，保留阅读位置，旧确认不得继续。
- 当前需求的精确审批/工程方案展示前加载完整单条；六类工程审批入口写前重新读取。
- 完整详情cache最多8条、32MiB UTF-8，单条最多16MiB；历史正文关闭/切换后释放。
- 每页25条，显式上一页/下一页/返回最新让完整历史都可到达；保留最近4页可回退，cursor stale时明示重读，不混合不同inventory。
- DOM/控制协议增量测试通过，不调用生产API/SQL、不中断K1或修改主仓。

## 存量与回滚

无需改库、改写历史或重建需求。空闲受控部署加载兼容backend/frontend后刷新原需求。
回滚前端恢复原读取路径，保留全部持久化记录；不能删除新摘要背后的完整记录。
