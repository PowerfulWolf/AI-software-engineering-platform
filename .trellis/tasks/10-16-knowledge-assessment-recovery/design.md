# Exact rejected-returned knowledge proof and lifecycle

## Contracts before implementation

Introduce one shared pure assessment validator for redaction and exact same-run READ membership.
Known CLAIM_WITHOUT_READ and ASSESSMENT_REQUIRES_REDACTION are model semantic failures, never
store/policy failures. A knowledge-specific StructuredModelError carries INVALID_OUTPUT,
transient=false/retryable=false, a fixed reason and the exact sealed rejection observation.
The observation is a current recomputable fact, not a backdated invocation outcome or verdict.
It binds scope/Task/work/role/attempt/dispatch/checkpoint/source, actual historical claim SHA,
Run/Context/snapshot, intent and assessment outcomes, independently reopened execution receipts,
the complete validated READ manifest and fixed reason. Export exact typed schema as appropriate.
Unknown/incomplete/raw unsafe data never authorizes recovery. Do not retain invalid secret text.
The rejection observation requires an already safely sealed RETURNED result. The earlier
KnowledgeInvocationResult.from_result secret guard can reject before publication, leaving an
intent without an outcome; preserve UNKNOWN and deny this recovery rather than persisting the
sensitive response or synthesizing an outcome.

At online delivery, existing _knowledge_failure routes the typed error to INVALID_OUTPUT wait
with digest-only knowledge-assessment-rejection evidence. Catch other KnowledgeError in Worker
only to owner-fence PLATFORM_BUG wait/release, after preserving KnowledgeGapRaised and existing
wait boundaries; safe diagnostic uses fixed codes. Generic invariant errors grant no new recovery.

Use a sibling exact legacy proof/reentry scope under Task flock, without widening stopped-Coder
proof. Require sole old expired RUNNING claim, matching blocked invariant checkpoint, actual
semantic rejection recomputation, complete real native stops, exact original Context/READ/snapshot,
no main invocation/outcome/accepted/raw artifact/route/tool execution and intact complete workspace.
These main-execution exclusions apply only to the target original WorkItem/claim and its carry
successors. Retain all earlier main calls and accepted progress; current knowledge routes and
their independent stops must be present, not mistaken for forbidden main routes.
Append only a new DELIVERING Requirement checkpoint. Dispatcher performs actual expiry/reclaim.
Before any model/knowledge call, fresh Worker reopens original rejection and records an actual
fresh-claim carry/refusal observation, then owner-fences INVALID_OUTPUT wait/release. No same-work
model retry, expired-owner mutation, fabricated past refusal or manual SQL reconciliation.

Add distinct RETRY_REJECTED_KNOWLEDGE_PREPARATION evidence/resolution to existing engineering
Inspect/Resolve/Continue API. Do not reuse local-limit finite doubled timeout evidence or
RESUME_UNINVOKED. Seal independent current observation and exact manual/policy authority, then
recompute under Task flock and final MySQL fence. Validate original and any fresh carry claims,
full no-main proof, workspace/input freshness and remaining frozen work. Atomically consume one
ordinary work attempt, close old wait, reserve a fresh work/step once; preserve source, progress,
timeout window, provider failure counts and all old records. New claim/Run/Context only.
An automatic decision must already be covered by exact frozen engineering capability and limits;
otherwise explicit engineering principal authorizes. No prompt can expand either permission.

## Validation matrix

| Facts | Expected behavior |
| --- | --- |
| Genuine unREAD citation / semantic rejection with safely sealed complete RETURNED | Precise nontransient rejection, original RETURNED retained, owner-fenced wait |
| Secret guard rejects payload before RETURNED publication | Preserve intent/UNKNOWN and sensitive-data guard; no semantic recovery authority |
| Valid response or repository-owned GAP | Existing accepted consultation/fallback behavior |
| Generic store/path/schema/integrity KnowledgeError | PLATFORM_BUG wait/release, no semantic recovery authority |
| Existing KnowledgeGapRaised | Existing knowledge gap/wait unchanged |
| Exact expired legacy no-main rejection | Reentry then fresh-owner refusal, zero new model calls |
| Live/unknown stop, wrong source/claim/READ/scope, late main/route/raw artifact or unknown claim | Refuse without new queue/model facts |
| Exact rejected-knowledge resolution | Ordinary work+1 once, fresh identity, full draft/accepted progress retained |
| Budget exhausted, stale proof, missing capability/principal, concurrent active claim, tamper | Refuse, no refund/new work |
| Real native public recovery | Same original Task reaches independent QA/Review on one candidate |
