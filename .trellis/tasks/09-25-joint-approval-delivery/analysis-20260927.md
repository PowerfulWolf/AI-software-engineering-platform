# Bug Analysis: wait lifecycle and native UI temporary data

## Follow-up: executor evidence could not reach ASE Coder

1. Root cause (B/D/E): repair authority assumed every prerequisite already had a sealed QA
   completion. A controlled UI executor can fail before a model starts, so Manager received
   evidence but had no typed proposal path back to Coder. More diagnostics alone could not close it.
2. Prior fixes connected executor failures to Manager and added child-only diagnostics; neither
   supplied an alternative, truthful repair evidence type. Manufacturing QA would violate lineage.
3. Prevention: sealed `CandidateExecutorPrerequisite`, exclusive repair source types, optional
   exact Manager-advice binding, separate human approval and ordinary serial dispatch. No new
   source/command authority belongs to Manager. Legacy hash and schema-negative tests included.
4. Expansion: restart context, failed-continuation validation, Reviewer failures after QA admission,
   non-QA Console facts and current source/base/scope checks. Real Git/MySQL covers both source
   types, fresh Host before Coder, new candidate and independent fixture QA/Reviewer to DONE.
5. Knowledge: prerequisite-repair.md, verification-environment.md and docs/contracts.md updated.
   No template mirror exists; preserve the dirty user workspace rather than automatically commit.

## Follow-up: executor failures skipped Manager

1. Root cause (B/C/D): the coordination path was bound to inconclusive QA, but an executor failure
   occurs before a model/verdict. Both the immediate catch and the admitted-without-completion
   restart branch bypassed the Manager. Advice input lacked the new execution receipt entirely.
2. Earlier fixes covered creating UI plans, not consuming failed executor observations. A generic
   message labelled "Manager" was not an actual Manager decision.
3. Prevention: two red controller tests reproduced both bypasses; add coordination on both paths,
   exact final receipt lookup and reference validation, bounded failure context, first-failure
   support without inventing QA, current-input guard allowing only exact admitted run additions.
4. Expansion: verified source drift/candidate filtering, restart reuse and receipt tampering.
   Other stage/CLI capability audits remain separate; this repair does not make a universal
   environment installer. Window absence remains undiagnosed until Manager coordinates evidence.
5. Knowledge: verification-environment.md seven-section contract, docs/contracts.md and task design.
   The native failed receipt and historical approvals are unchanged. No business edit or GUI probe.

## Follow-up: Manager proposals and CLI authority

1. Root cause (B/D/E): production Manager only recorded a generic WAITING_HUMAN incident, while
   UI scenarios required an external caller. Separately, CLI QA used native shell plus post-run
   Git checks; the model allowlist did not mediate those shell calls. The live report claimed an
   inner-sandbox exception, but its actual command transcript has not been fully audited.
2. Why earlier fixes were incomplete: adding a bounded UI executor does not let Manager construct
   a plan. Adding WorkspacePolicy to Responses does not restrict the separate CLI execution path.
   Disabling shell alone still leaves apply_patch in the actual CLI tool catalog.
3. Prevention: durable exact-input Manager advice + fresh exact plan; no-command/read-only CLI
   verifiers consume exact candidate snapshots/controlled receipts. Real local mock-provider test
   inspects tool catalog and attempts a denied patch. Original criteria and independent verdicts stay.
4. Expansion: other CLI roles still need an independent typed-tool audit; the no-command verifier
   slice fails closed on missing test receipts instead of silently widening command authority.
   Full contract suite also exposed generator overwriting custom JSON Schema constraints: retain
   cross-field validators explicitly in the generator and test canonical negative payloads.
5. Knowledge: updated verification-environment.md, docs/contracts.md and task design. No template
   tree exists. Preserve user's dirty worktree; no automatic commit, merge or production fact rewrite.

## 1. Root Cause Category

- B/E (cross-layer contract / implicit assumption): queue wait released a claim while the
  independent heartbeat could renew it. Local execution checks also continued to pass after wait.
- D/E (test gap / implicit assumption): the native UI read-denial test depended on pytest placing
  its fixture below `/private/var/folders`. A fresh `/tmp` basetemp exposed readable host temp files.

## 2. Why Fixes Failed

- Merely setting the heartbeat stop event after SQL wait leaves a release-to-stop race.
- Recovery-to-parent attachment alone does not prove successful fresh-process continuation. The
  production-style fixture used a legacy QA report with no tests_run and was correctly rejected by
  WORKFLOW_QA_TEST_EVIDENCE_REQUIRED. Keep that gate; record the fixture's actual candidate check.
- UI launch and isolation success still do not prove interactive acceptance. A locked desktop
  produced SESSION_LOCKED; after the user unlocked, the full platform fixture passed.

## 4. Systematic Expansion

- Retain transactional expiry and owner checks; local lock is not database authority.
- Preserve Task/candidate and knowledge history when yielding to Manager; do not map normal wait
  to invariant failure or invent a QA verdict in Console.
- Use a fresh explicitly retained basetemp for long integration diagnostics. Keep MySQL suites
  serial because their guarded fixture resets only the isolated test database.
- These are platform fixture results, not business acceptance or permission to merge/deploy.
