# Exact rejected-candidate execution input

The original invocation completed and produced a real clean candidate, but its Artifact schema_version was unsupported and never entered the accepted ArtifactStore. Those facts are distinct from FAILED output without an artifact, rejected Coder progress, ordinary candidate-ready verification and UNKNOWN execution. Existing capabilities remain strict.

New `RejectedCandidateOutputProof` embeds the original immutable outcome/start/stop/claim, original Task/step/scope, unsupported implementation, exact candidate and single parent equal to the original execution source, complete candidate diff/capture and unfiltered clean inventory. Current collection independently verifies Git, permissions, protected/native rules, no accepted publication/adoption and actual stopped processes under the existing Task/idle queue fence. A digest alone never grants readiness.

`BaselinePurpose.REJECTED_CANDIDATE_RESCUE = rejected_candidate_rescue` is target-free. `facts.rejected_candidate_output`, `reservation.rejected_candidate_output_sha256` and `binding.rejected_candidate_output_sha256` are optional and omitted when None, preserving historical hashes. Their association is bidirectional and mutually exclusive with every other rescue proof. Reservation reason is `rejected_candidate_output`, with exact original invocation IDs/digests, next attempt current+1, ordinary frozen work, no refund and no already-applied flag.

Plan target_base_ref and Binding.execution_base_ref remain the prior execution base (554 for K1); prepared_source_revision and execution_source_revision become the proved existing candidate (308bf). Task.base_ref, original Product/native rule baseline and prior execution source stay immutable. Preparation and execution perform no Git mutation; before/after complete inventory is identical, no reapply or conflict mode, no native rule change. Binding source advancement is append-only execution lineage.

New purpose requires exact human ENGINEERING decision with PAUSE (delegated authority comes from user authorization), then a separate exact latest-binding RESUME. Reopening and queue consumption independently revalidate original proof, clean inventory, native rule hashes, original budget/claim and idle status. An expired RUNNING lease alone never proves stop; only the exact stopped invocation can be closed while consuming this decision. Replay is idempotent, not another reservation.

A new normal claimed Coder may complete missing original acceptance work or issue a correct fresh report about the retained candidate. If no source change is needed, a narrow consumed-binding admission may allow reporting the existing candidate after verifying its entire original execution-base diff and clean unchanged workspace; ordinary Coder runs still require a new nonempty candidate. This permission cannot come from request text, attempt count, arbitrary HEAD, unsupported old artifact, or an unconsumed proposal. No meaningless change is required merely to cross the old new-commit gate. All accepted output remains v0.1 and must pass exact identity, lineage, complete changed-file and evidence checks before normal independent QA/Review.

Validation: positive actual Git+isolated MySQL same-Requirement public flow; unsupported reason/version drift, missing stop/claim, wrong candidate/parent, dirty/index/ignored/secret/protected/native-rule drift, existing publication, mixed proof, exhausted budget, foreign authority, RESUME at approval, repeated/stale decisions, ordinary no-change Coder rejection and historical wire equality.
