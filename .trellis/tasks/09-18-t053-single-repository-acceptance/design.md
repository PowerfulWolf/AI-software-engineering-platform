# Design

`SingleRepositoryAcceptance` is a parent-journal fact, not synthetic integration evidence.
The production backend obtains it by rebuilding the exact native delivery runtime, reconciling
the committed child checkpoint, and returning its sealed terminal artifact or candidate-
verification references. The joint service may write DONE only when the proof matches the
only scope unit and the complete ProductSpec acceptance IDs.

For historical integration recovery, `JointJournal.history()` supplies the last approved plan
to an in-memory validation checkpoint. No historical record is changed and no attempt counter
is reset. Multi-repository plan validation retains the existing coverage and interface rules.

The read model projects the pre-finalization state as `WAITING_DELIVERY_FINALIZATION`; this is
a user action boundary, not a claim that Planner is running.
