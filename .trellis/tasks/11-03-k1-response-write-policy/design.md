# Design

The Task's approved `write_paths` includes `src/ai_software_engineer/artifacts/accepted.py`. `WorkspacePolicy` accepts it, while `PolicyBoundToolRegistry._authorize_role_write` currently rejects any path component named `artifacts` regardless of position. Its purpose is to prevent a role from writing delivery artifacts, not source code with that package name. Limit the additional role guard to reserved artifact/state/verdict paths and explicit report outputs, after `WorkspacePolicy` has enforced the Task grant and symlink containment. Keep the existing fixed `PATH_DENIED` response; do not surface raw request paths in public diagnostics.

The completed K1 Run has a final Responses route and matching `POLICY_VIOLATION` outcome, with no native capture stop. Its three retained test files predate the failed Run. A new terminal snapshot variant may admit only the exact `write_file/PATH_DENIED` message and prove `start.inventory_before == current inventory`, complete legal capture, no new mutation, a closed claim and terminal Task. The variant authorizes a new `coder_reapply` RecoveryPlan only. It does not claim the attempted write was lawful. The new Task must enforce its own approved write paths, including the corrected source-module policy, and complete QA/Review.

The existing `responses_tool_refusal` v2 path covers empty worktrees; the K1 retained draft needs an additive variant with explicit wire guards. Synchronize Pydantic, static Schema and generator. Public Continue/approval remains the only production mutation path. No direct database change or old Run edit.
