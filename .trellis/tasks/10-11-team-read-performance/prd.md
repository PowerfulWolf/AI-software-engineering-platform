# 团队视图读取性能与刷新调度

## 目标与已知事实

真实只读生产 snapshot 耗时 7.552 秒及 5.993 秒，响应 2.47 MiB；序列化仅 0.009 秒。完整 Task 投影与联合历史核验占主要成本。单页已串行读取，但固定五秒时钟使慢读取后很快再次读取；其他标签页或已取消而未结束的后台读取会触发全局内存保护锁的 503。当前没有永久持锁或新内存泄漏的证据。

## 范围

- 在现有只读 reader/store seam 减少可证明重复的核验工作；保持完整历史、完整字节与路径/hash/前驱/身份校验。
- 自动刷新在实际本轮完成后安排下一次；忙碌或超时以有界退避避免持续抢读，并保留明确的旧数据提示和操作门禁。
- 保留手动刷新、最新 Project 意图、编辑/滚动状态、独立恢复进度与模型事实的语义。
- 不改变 TeamSnapshot HTTP/schema，不排队 reader，不删除全局 worker 互斥，不缓存跨请求 snapshot/权限/活动状态。

## 验收

- [x] 先有可复现慢读/重复核验的工作量测试或轮询调度回归测试。
- [x] 新尾记录、历史篡改、缺失、异项目、退休与 public 返回对象修改保持原有拒绝/隔离。
- [x] 缓存若使用则明确限条数、字节数、作用域与释放；每次重新读取完整历史字节。
- [x] 单页不会在未完成读取之后立即补一个过期 tick；busy/timeout可自动恢复，手动刷新与项目切换仍及时。
- [x] 增量 Python/DOM/真实浏览器相关测试、scoped lint/typecheck通过；不跑全量。
- [x] 独立复核；在隔离 worktree 完成，不在活跃生产执行中修改运行源码或重启。

## 存量数据处置与回滚

只读性能与客户端调度变更无需改 SQL、Journal、需求、审批、Task 或工作区。所有旧记录保持原样；空闲后受控部署。回滚代码恢复原读取成本/轮询频率，不回滚真实交付事实。
