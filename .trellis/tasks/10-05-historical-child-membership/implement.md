# Implementation

- The reader captures all validated parent histories, checks every retained Team/Project binding,
  reads native chains, then folds typed permanent membership before retired/native filtering.
- `_joint_scopes` owns exact historical/current child validation and unattached plan identity
  derivation. Attached child observations must be exact native history ancestors with matching
  known unit and code root; membership cannot conflict across parents, units or scopes.
- Current Requirement scopes are independently projected from the newest checkpoint. Historical
  TaskViews keep their original facts and regain the exact original parent's `request_id`.
- `_current_requirement_work` filters historical native sources and their candidate verification/
  remediation descendants from live parent composition. `_agent_views` preserves that work in
  member history while excluding it from current/assigned queues without changing terminal flags.
- Root-owned frontend changes share current-scope selection across header/flow/blocked member
  queues/counts and add a folded historical-delivery list with original task-detail links. Exact
  Project and parent IDs bound the history classification; same-title standalone work is preserved.
- Incremental tests include read-before/after byte inventories, cleared current windows, later
  child, same-title standalone, historical corruption/ambiguity, native prefix advancement and
  descendant/member live-isolation. No persisted Schema or authority contract changes.
