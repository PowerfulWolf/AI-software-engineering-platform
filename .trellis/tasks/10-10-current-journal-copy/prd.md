# 联合交付 current 的返回值复制优化

## 目标与范围

恢复前置核验频繁调用 JointJournal.current。当前实现通过 history 读取最终状态，因而在每次
完整读验之后深复制所有历史模型，尽管只返回最后一项。本任务仅消除丢弃的历史返回副本。
完整文件读取、Schema、摘要、文件名、前驱链和有界验证复用仍按既有契约执行。

允许路径见 task.json。不涉及审批、权限、状态机、数据库、日志截断或生产操作。
现有恢复计划的目标基线 5d121a107fbbd7b5d1341ce4aff8bfc6ecb32874 保持不变。

## 验收标准

- 用真实离线日志链及真实 model_copy 计数先 RED 再 GREEN：非空 current 只深复制一次，
  history 仍逐项深复制；空日志不复制。
- cold/warm 每次读取所有完整文件字节；只有完全相同字节与前驱的既有验证可复用。
- 同长度且恢复 mtime 的历史篡改、删除初始/中间记录、重封祖先却不更新后继、错误文件名
  或 symlink 均拒绝。有效追加在下一次 current 中立即可见。
- 返回模型中的嵌套 dict 修改不污染私有验证缓存或后续返回；原 512 项 cache bound 保持。
- 仅运行新增及相关增量测试、Ruff、strict Mypy、diff check，交 root 独立审查。

## 存量数据处置与回滚

无需修改持久化事实：既有日志、Task、Operation、授权、恢复计划和历史字节继续完整验证。
加载修复版本后仍使用原需求和原恢复路径，不新增需求、不补造旧执行结果、不替用户审批。
回滚 store.py 的遍历提取即恢复旧复制成本；持久化格式和权限不变。
