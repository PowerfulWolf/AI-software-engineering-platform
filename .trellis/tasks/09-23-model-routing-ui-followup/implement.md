# 实现与失效模式

- Agent 职责说明改用现有可访问弹层，摘要不再显示小字；弹层点击与关闭阻止外层 `<details>` 意外展开。
- 单 Agent 详情恢复横向主模型字段，移除内层 `<details>` 继承的 12px 默认外边距，精确对齐标签与选择框；备用行/添加入口使用同一 122px 内容起点，小屏按字段顺序堆叠。
- 当 Agent 已选满当前启用模型时，添加备用模型入口仍提供“新增可用模型路由”；新路由初始停用，配置并启用后仍需用户明确选择为备用，绝不自动改变策略。
- Status 展示兼容 `kind` 与 `route_kind`：Responses API 使用 `kind=responses`，Codex CLI 的历史未知 transport 保持未知。
- 模型目录默认全折叠，添加只展开新项；全局 `render()` 不再把所有无 `data-key` 的 `<details>` 作为同一个空 key 恢复，这是新增路由时旧项全部展开的根因。

根因分类：前端展示契约与 DOM 状态恢复叠加。之前的测试仅验证存在可选备用路由时的添加操作，没有覆盖全部路由已分配的边界；Status 测试未断言 Responses 类型文案；详情布局未对标签和控件中心做几何断言。对应回归已补入目标测试。
