# Design

`LegacyExecutionContainment` validates the original `QueueClaim.model_selection.route_kind` as either `codex_cli` or `responses`. The old CLI reboot contract remains. Responses must always use `method=operator_confirmed_local_stop`, with a complete same-device, same-account survey of the manager-owned original checkout, including after a later host reboot. The trusted collector chooses that method from the frozen original claim, not a caller field. Unknown/mixed fallback routes, late outcome/stop/receipt and changed capture remain rejected by the existing collector.

The original Responses HTTP model request cannot directly write the local checkout; only the locally owned ASE tool loop can. The declaration therefore attests that the original local invocation and every derived tool have ended and cannot write again. It does not claim a provider result or historical stop proof. Existing Plan, authorization, Task/queue CAS, HumanActionEvent and subsequent role gates are reused. No wire field changes. All seven embedded static Schemas must enforce the route-dependent method and survey guard that the Python validator enforces. Responses also requires an original claim with an immutable CLAIMED-event snapshot; a legacy reconstructed claim is insufficient for this new path.

Good: frozen Responses start-only claim, idle complete survey, exact operator stop declaration, unchanged draft → same-Task new Coder Run. Base: native CLI reboot/local-stop recoveries preserve their existing wire and behavior. Bad: Responses reboot-only, active worktree process, route final, outcome, stop or changed draft → no plan consumption or new model request.
