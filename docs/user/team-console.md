# 团队工作台

## 使用

按照 [生产配置](../operations/production-setup.md) 安装后启动本地 Web Console；未配置时可先在页面完成设置：

```bash
uv run ase-console
```

打开 **http://127.0.0.1:8765**（使用该地址，不使用 localhost 别名）。页面可以创建多目录需求、
与 Product Agent 讨论和批准、继续中断交付、批准 exact 恢复计划，以及领取 Candidate。
Ctrl+C 会停止控制台和它的后台 Manager dispatcher；已经提交的 Operation、Delivery、Task
和 Artifact 仍然持久化。页面在本轮读取完成后等待 5 秒再自动更新；平台繁忙或读取超时时会稍后
重试，并保留上次内容和读取时间。手动刷新与切换 Project 会立即请求更新，不要求手工拼装 ProjectionFacts。
控制台页面和操作能力绑定本次服务启动。更新平台代码后，等待当前操作及角色执行结束，
在服务空闲时运行 `./scripts/ase-console-service.sh restart`，再刷新页面；仅刷新无法加载新的
后台操作。页面遇到版本不匹配会给出中文说明并阻止提交，原需求和已保存进度保留。
脚本会先进入受控收尾，等待现有写入、Operation、后台索引和执行进程真正结束并保存记录。超过等待时限
会保留原服务并拒绝替换；可稍后重试，若服务仍在且只是等待超时，可执行 `resume` 解除排空。
完整操作与旧版升级说明见 [受控重启](../operations/controlled-service-restart.md)。
故障替换后若显示“维护仅查看”，展开顶部的“完成维护并恢复普通模式”，按
[维护完成指引](service-maintenance.md)在本机核验与确认；原暂停需求不会随服务模式自动继续。
配置缺失时进入 setup 模式，设置和状态页仍可访问；端口占用时 CLI 安全退出。
Team 未准备、数据库不可用或记录校验失败时交付不可用并显示具体状态，
不伪装成空团队。真正空的已准备 Team 显示创建 Project/接单提示。

## 三条阅读路径

1. **团队成员**：Team 成员、岗位、启用配置、跨 Project 多项分配、当前岗位阶段、分配模型与历史任务。
   一个 Agent 不随项目复制，当前任务也不是单值字段。
2. **需求与交付**：所有选定代码目录/模块、只读参考目录、各仓进度和整体验收状态。
   点击需求看联合 ProductSpec、TechnicalDesign、ExecutionPlan、IntegrationEvidence，并执行当前唯一
   合法的 Product 回复、批准或继续操作。
3. **任务详情**：Task 状态、最近活动、阻塞、候选 SHA、时间线、实际模型路由尝试的结果、
   耗时和失败分类，以及已通过状态事件引用的 plan/implementation/QA/review 报告。
   联合文档、选中需求的 ProductSpec 和四类交付报告提供脱敏正文。

当前状态和完整正文分别读取。打开需求或任务后，上方状态继续更新，正文区域显示
“正在读取所选记录的完整正文与历史”；读取完成后可以查看全部产物和返工记录。
相同版本的自动刷新保留正文、展开位置、选中文字和滚动位置。新 QA/Review 反馈保存后，
对应完整记录会重新读取，不限制为最近 8 条。

正文暂时读不到时，页面会保留上次读取的内容并说明其版本，同时提供重新读取入口。
这表示页面读取失败，不代表没有历史或交付失败。若提示记录已有更新，点击
“刷新当前状态并重新读取”；状态和正文都来自当前版本后，再进行相应操作。
批准 ProductSpec 前必须成功读取当前完整规格；旧正文或未完成的读取不能用于批准。

记录在调用完成或阶段提交后发布，不显示模型私有思考或未提交聊天。报告 SHA 指向原始已验证
事实，展示正文再次脱敏后不应拿展示字符串计算源 SHA。

遇到工程等待时，产品用户不需要检查 lease、进程号、补丁摘要或工作区。需求详情会直接显示
“让平台处理中断”，并给出当前原因、处理方、具体动作和复查时机。平台会在原 Task 的受控范围
内执行一次有界核验；若已具备冻结授权和完整事实，Manager 会交回原 Supervisor 继续；若记录
不完整，会保留现场并显示“平台需要维护”，不会把产品用户变成维护者。只有页面明确显示需要
工程职责决定时，才由有工程权限的维护者处理精确决定。重新检查只重新读取事实，不会补造执行结果。

如果交付按钮暂不可用，需求详情会直接显示原因与下一步。比如“交付操作记录读取失败”表示
页面暂时无法读取已保存的方案与审批，不能据此认定方案准备失败或不存在。等待平台修复读取后
刷新原需求，再查看方案并确认；不需要重复准备、清空进度或重新创建需求。后台服务、交付运行时、
Team 绑定或项目切换导致不可用时，按该处对应提示处理，关闭全局通知不会隐藏说明。

批准保留进度的恢复方案后，需求详情会直接显示平台已记录的准备明细，例如授权核验、
恢复输入封存、派发保存、保留改动核验与开发领取，以及各项实际观察时间。这些说明帮助你
了解平台完成了什么；开发是否正在运行仍以上方当前节点为准，领取记录不代表代码或验收通过。
如果需要开发重新适配旧进度，页面会明确说明，不会把准备完成说成旧改动已经合入。

准备明细单独刷新，团队记录暂时读取较慢时仍可查看。旧操作可能没有记录准备明细；暂时
读不到明细也不代表执行失败，页面会保留上次读取的内容并标记时间。无需重复批准、重建需求
或为了查看进度重启服务；当前需要人工决定时，仍按本页明确显示的方案与按钮处理。

如果原需求显示“输入超过模型容量 · 交付暂停”，表示平台在本轮主开发调用开始前发现输入超限，
原需求、分支和已有开发进度仍保留。平台需先修复模型输入准备或执行配置；不需要重建需求、
清空文件或填写代码版本。修复后，在原需求详情依次操作：

1. 点击“准备保留进度的恢复方案”。平台核对当前容量等待并完整保存合法开发进度；准备本身不启动开发。
2. 方案准备完成后，核对页面说明，点击“批准保留进度，保持暂停”。此决定保持原代码版本和开发现场，
   交付仍暂停，不代表模型通道已恢复或需求已完成。
3. 页面显示“进度已保留 · 交付暂停”后，点击“继续原需求”。平台重新核验输入并接续原任务，
   完成开发后仍需独立测试与评审。准备、批准和继续分别记入原需求的交付记录。

准备失败时，按卡片列出的原因修复后重新准备；完整记录读不到时，先恢复平台读取，不能用旧页面批准。
旧服务不支持此操作时，页面会明确提示更新服务，且不会提交新恢复请求。只有你确实要纳入目标仓库
的新代码时，才使用另列的“可选工程操作 · 更新原分支基线”；容量恢复本身保持原代码版本。

## 不能混淆的状态

- IMPLEMENTING / QA / REVIEW 是交付 checkpoint，不是进程存活证明。
- 当前岗位由 Task 状态和 DispatchPhaseCommit 对齐；预分配 QA 不会提前标为正在测试。
- enabled、max_parallel_assignments 是配置，不代表在线状态或实时全组织容量占用。
- Project 过滤只影响需求与交付视图；Team 成员与总负载仍属于唯一 Team。
- 没有 heartbeat 时 execution_liveness=UNKNOWN，不能仅靠超时猜测进程失败。
- 分配模型来自 ModelSelection；实际调用模型来自 ModelRouteAttempt，降级记录不会被原始分配覆盖。
- 调用成功不等于 QA/Review gate 通过；一个子仓 DONE 不等于多仓需求 DONE。
- 上游岗位未登记为独立 AgentProfile 时，只在需求阶段显示，不生成虚构成员。

刷新失败保留上次画面并标记“旧数据”和成功时间；无变化的刷新不替换 DOM，有变化时保留已展开
历史/报告，避免阅读中被自动刷新折叠。

## 放弃等待中的旧需求并重新开始

交付停在工程等待时，例如验证环境尚未就绪，可以在需求详情选择“关闭需求”。平台会核验该需求
全部历史执行都已停止，且只有当前工程等待尚未结束，再记录取消决定、结束旧 Task 和队列，最后
保存“已关闭”。仍有执行进程、有效执行许可或无法核验的记录时，关闭会被拒绝，原现场保留。
按这种方式取消工程执行后，应基于当前工作空间新建需求；旧执行不能用“重新启动需求”复活。
空闲的产品草稿和已停止的阻塞需求也可关闭；平台只提供关闭、删除，不提供归档。

关闭成功后，重新读取“已关闭”需求再点击“删除需求”。删除使用关闭后新记录的精确身份；先前的
关闭或删除失败记录保留。删除让旧需求及其子任务退出产品列表与 Agent 队列，并释放旧执行权；
平台先将受管工作区中的完整草稿（包括暂存、未跟踪和忽略文件）私密保全，再释放临时工作区。
完整审批、候选提交、Task、队列和证据历史仍用于审计；共享数据库和项目源码保留。重新创建同名
需求会获得全新身份，重新经历 Product 规格批准、设计、计划、开发、QA 和 Review。

资源保全失败时，页面显示未完成释放的原因；检查后可重试同一关闭或删除，平台核验原记录并继续。
尚未结束的独立验证、活跃进程和有效许可仍会阻止清理。已完成需求可以直接删除。
需求列表不再展示汇总操作记录；具体过程在需求详情查看。删除后相关操作不再进入日常列表和计数，
底层完整审计保持可查。保全路径为项目requirements下相应需求的resource-archives目录。
