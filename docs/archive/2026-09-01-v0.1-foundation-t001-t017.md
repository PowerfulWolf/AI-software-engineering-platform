- 完成任务：T001–T017
- 里程碑状态：M0–M4 完成；M5 已由 T017 启动

## 总结

这一阶段把项目从一份架构设计推进成了可运行、可持久化、可恢复、可审计的串行 AI 软件工程
控制平面。Task、Agent、Context、Artifact、StateEvent、EvaluationEvent 与 Handoff 都有明确
类型和持久化边界；Coder、QA、Reviewer 通过 artifact 交接；Git worktree、命令执行和项目
sidecar 开始形成隔离层。

它还不是“给一个目录和需求，就能完全自治交付”的最终系统。T001–T017 建立的是后续实现
ProjectProfile、规范冲突治理、Agent tool protocol、证据封存、真实项目 E2E 和可视化所需的
可信地基。

## 阶段 0：设计基线与 Bootstrap

范围：初始设计、T001。

完成事项：

- 固化三条组织原则：知识属于组织、Agent 不能单独裁决自己的工作、角色通过可验证 Artifact 沟通；
- 定义 v0.1 串行状态机和 Coder/QA/Reviewer/Orchestrator 权限边界；
- 建立 README、AGENTS、`.trellis/spec/`、JSON Schema 和架构文档基线；
- 选择 Python 3.12、Pydantic、SQLite、Git CLI 与 uv，并记录语言架构决策；
- 创建可安装 Python package、`ase` CLI 入口和首批测试骨架。

证据：bootstrap `6138cb1`；T001 feature `4b79025`。T001 完成时累计 5 tests。

## 阶段 1：组织事实与持久化

范围：T002–T005，对应 M1 Domain + Persistence。

完成事项：

- 建立 Task、Agent Definition、Artifact 与四类角色 Artifact 的强类型领域模型；
- 实现 SQLite Task snapshot + append-only StateEvent repository，支持幂等写入和重启恢复；
- 实现纯 Task state-machine guard/reducer，非法迁移 fail closed；
- 实现不可变、原子写入、SHA-256 校验和 lineage 校验的 ArtifactStore；
- 建立 Python model 与 canonical JSON Schema 的双向契约测试。

核心不变量：Task 状态不能被任意字段更新绕过；Artifact 内容、来源 revision 与父子关系一旦
封存就不能静默改变。

证据：T002 `fc1fd77`、T003 `2e7ed76`、T004 `e6c869f`、T005 `b08ab8c`。阶段完成时累计 111 tests。

## 阶段 2：Repository 与 Context 隔离

范围：T006–T007，对应 M2 Git + Context。

完成事项：

- 为 Coder 创建 attempt branch worktree，为 QA/Reviewer 创建 candidate SHA detached worktree；
- 建立路径、命令、分支命名和 dirty cleanup policy；
- Context Builder 对输入排序、规范化、脱敏、预算裁剪并生成稳定 manifest；
- Context Router 按角色只提供契约允许的上下文，避免共享隐式会话；
- 对路径穿越、越权写入、secret 注入和不确定上下文采取 fail-closed 策略。

核心不变量：QA 与 Reviewer 不复用 Coder 的可写工作区；同一输入得到稳定 Context manifest；
被裁剪或拒绝的上下文必须显式可见。

证据：T006 `bd52bc4`（integration `32deb8e`）、T007 `402c49f`（integration `2076491`）。阶段完成时累计 150 tests。

## 阶段 3：串行 Agent 交付闭环

范围：T008–T011，对应 M3 Serial Agent Loop。

完成事项：

- 实现可确定性注入成功、QA FAIL、Review REJECT、timeout 和 typed failure 的 FakeAgentAdapter；
- 实现固定 `planning → coder → qa → reviewer` 的串行 Orchestrator happy path；
- QA FAIL、Review REJECT 路由回 Coder，并受 attempt、token 和失败分类约束；
- checkpoint/recovery 能从 durable Task、Event、Context 和 Artifact 恢复；
- 实现 OpenAI-compatible AgentAdapter 与 FileContextStore，fake/real adapter 共用 typed contract。

核心不变量：Coder 不能为自己产生 QA/Review verdict；路由结果来自 typed Artifact 和状态守卫，
不能从自由文本猜测；中断恢复不能补造历史。

证据：T008 `7143b46`、T009 `3ea3523`、T010 `4f3ed83`、T011 `52ee828`；阶段 integration 基线 `2a74537`。阶段完成时累计 213 tests。

## 阶段 4：Evaluation、Handoff 与可操作 Runtime

范围：T012–T014，对应 M4 Evaluation + Human Handoff。

完成事项：

- EvaluatingAgentAdapter 在 Agent 执行时记录 durable EvaluationEvent；
- EvaluationTraceBuilder 与 EvaluationEngine 从事实重算指标和 Autonomous Delivery Rate；
- 缺少回归观察窗口时 ADR 明确为 `PENDING`，不会把未知伪装成成功；
- HandoffBuilder 为 DONE/BLOCKED 生成自包含 JSON + Markdown 人工交付包；
- CLI 提供 `task create/show/events`、`evaluation report`、`handoff build`；
- RuntimeConfig、RuntimeSession 与 `task run` 组装真实 provider、stores、角色路由和 retry runner；
- provider secret 只从部署环境读取，不进入 config、Artifact 或日志。

核心不变量：指标必须能从 durable facts 重算；CLI 只是 composition root，不能越过领域契约
直接改状态或 verdict；handoff 不执行 merge。

证据：T012 `e2ecaf4`、T013 `601ffb3`、T014 `905b5ef`；T014 verification 基线 `50b9dfd`。阶段完成时累计 254 tests。

## 阶段 5：执行安全边界

范围：T015–T016，为 M6 的真实工具执行预先建立安全 seam。

完成事项：

- SubprocessCommandExecutor 只接收 tokenized argv，使用固定 worktree cwd 和 command allowlist；
- 使用最小环境、`shell=False`、输出上限、进程组 timeout 与结构化 CommandResult；
- RoleWorktreeSession 校验 Agent role 与 WorktreeSpec 一致，并组合 manager-owned worktree 和 executor；
- Coder 使用 attempt branch；QA/Reviewer 使用 candidate detached worktree；dirty cleanup 保留现场。

核心不变量：自由文本不能直接成为 shell；命令执行成功不等于 QA PASS；当前 application seam
不会自动运行模型输出、迁移 Task、修改 verdict 或 merge。

证据：T015 `3dfef7d`、T016 `174426b`；阶段 integration 基线 `26283bf`。阶段完成时累计 270 tests。

## 阶段 6：任意项目接入基础

范围：T017，对应 M5 的第一步。

完成事项：

- ProjectWorkspaceRegistry 将任意本地目标项目绑定到稳定的外置 per-project AI workspace；
- 目标项目仍是代码、测试和构建命令 cwd，平台不复制源代码；
- sidecar 固定包含 profile、agents、knowledge、policy、state、artifacts、contexts、evidence、
  evaluations、handoffs、runs、locks、logs、spec-conflicts 等目录；
- ProjectWorkspaceManifest 记录规范化项目路径、workspace identity、版本和 SHA-256；
- 重复注册幂等，manifest 漂移、路径逃逸、非法项目目录和边界冲突 fail closed；
- 明确“项目原生规范不能被平台静默覆盖”，为人工规范冲突治理预留 `spec-conflicts/`；
- 完成 Agent 工作可视化的信息架构设计，但尚未实现 dashboard。

核心不变量：非业务 Agent 信息不能污染目标项目；sidecar 不是源码 checkout；目标项目规范与
平台规范冲突时必须交给人类处理。

证据：T017 feature `1d7393d`，integration `3ca68b4`。阶段完成时累计 283 tests。

## 归档时尚未完成的能力

以下内容不能被当前“已完成”状态所暗示：

- CLI 尚未自动发现或绑定目标项目的 ProjectProfile 与 sidecar；
- 尚未自动发现语言、构建系统、VCS、测试入口和项目原生规范；
- platform hard policy、项目规范和任务约束尚未通过 SpecCompiler 合并；
- 规范冲突尚未自动生成 typed `SPEC_CONFLICT` 并进入 Human inbox；
- Agent 尚未通过 typed tool protocol 调用真实编辑、Git inspection、构建和测试工具；
- 命令、diff、测试、usage 的 durable evidence capture 尚未接入真实 run；
- 尚未完成 Java/Go/TypeScript/Python 目标项目的串行交付 E2E；
- 事件只读投影、read API 和可视化 dashboard 尚未实现；
- 平台不会自动 merge 保护分支、部署生产环境或运行复杂并行 DAG。

下一阶段从 T018 ProjectProfile/native rule discovery 开始，完整顺序见
[`docs/milestones.md`](../milestones.md)。

## 归档后架构修正（2026-09-01）

上面的“下一阶段”是归档时的原始计划，现已被
[`ADR 0002`](../decisions/0002-organization-owned-agent-workforce.md) 取代。用户与平台共同确认：
Agent 应由组织拥有并通过 Assignment/Lease 服务多个 Project，模型按 AgentRun 分配；Project
不拥有一套 Agent。因此 T018 改为 Organization Workforce foundation，原 ProjectProfile 任务
顺延。T017 当时的 `agents/` sidecar layout 是准确历史事实；T018 将新 layout 升级为 v0.2 的
`assignments/`，不静默改写旧 manifest。
